WHAT PINS IT
------------
tests/window_hosted_body_spec.lua   — the live path (W.Open). Pass legs: no shown
  frame under the body paints a backdrop edge; the content frame (SF.ContentFrame)
  has no edge / transparent fill / zero insets; the chrome (SF.Chrome) is not
  created and, where it exists, not shown; no visible FontString carries the
  vendored accent (colour value AND colour code); the inner strip offers and
  switches Upgrades/Log/Settings; the Settings headings paint in T.Ledger("text").
  Negative legs: the same checkers must NAME a re-introduced border, a
  re-introduced teal string, a re-introduced title bar + close button, and the
  old bordered box put back on the real content frame.
tests/window_hosted_adoption_spec.lua — the other path: /ts builds the standalone
  window first (the pre-state is asserted: title bar shown, content frame
  bordered, accent strings visible), then the pack adopts it, and the same audits
  must be clean afterwards.

Harness visibility is EFFECTIVE, not own-flag: C.Visible walks the ancestor chain,
so a FontString under a hidden parent reports hidden. That was the model gap the
review named; using the child's own IsShown() reports a shown string under a
hidden title bar.
